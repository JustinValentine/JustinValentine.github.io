Uploaded to GitHub between November 2021 and August 2022. Code: JustinValentine/Rubiks-Cube-Solver.

This is a Rubik’s Cube program in Python, using NumPy and Tkinter. It started as a simulator that draws a cube of any size as a flat net and lets you turn its layers. I uploaded that in November 2021, and at the start of January 2022 I added a solver for the 3×3 that uses the beginner’s layer-by-layer method. I also wrote two OpenCV scripts for reading a real cube with a webcam, but they never got connected to the solver.

The simulator

The cube is a list of six faces, each an N×N grid of numbers from 0 to 5, one number per colour. The window draws the faces as an unfolded cross, with one Tkinter frame per sticker. A move is a short string made of an axis letter and a two-digit layer number, so x00 turns the first layer about the x axis and y02 turns the third layer about the y axis.

Turning a layer moves a row or column of stickers on each of the four faces around it over to the next face. If the layer is on the outside, the face itself also turns a quarter turn, which is a transpose plus reversing each row. Every move turns the same way about its axis, so turning the other way means doing the move three times. None of this depends on N, so the same code turns a 10×10×10. Mix applies random moves, 20 of them on a 3×3. On odd sizes it never turns the middle slice, so the centre sticker of each face stays put.

The solver

The solver only handles the 3×3. Each step finds the pieces it needs and applies a fixed sequence of turns for whichever case it finds. The net is drawn with orange on top and red on the bottom, and the solver works from the orange side to the red side:

  1. Put the four orange edges on the orange face, then line each one up with the centre of its other colour.
  2. Put in the four orange corners.
  3. Put in the four middle-layer edges with a left or right insertion sequence.
  4. Make a cross on the red face. The sequence depends on whether the red edges show a dot, an L or a line.
  5. Swap the last-layer edges until they match their centres.
  6. Move the last-layer corners to their places, then twist them until all the red stickers are on the red face.

Solve runs these steps on the cube in memory and records every move. A last pass merges repeats of the same move (four in a row cancel out, and three become one turn the other way) and writes them in cube notation, with i for an inverse turn and a leading 2 for a half turn. Then it puts the scrambled cube back and replays the moves on screen.

The README claims it can solve any of the 43 quintillion positions. Nothing in the repo tests that, and a comment I left on the middle-layer step says edges sometimes came out flipped.

How long the solutions are

The number of positions comes from counting pieces. The 8 corners can be arranged in \(8!\) ways and twisted 3 ways each, and the 12 edges can be arranged in \(12!\) ways and flipped 2 ways each. The twist of the last corner and the flip of the last edge are fixed by the others. The corner and edge arrangements also have to be both even or both odd, which halves the total:

\[ 8! \cdot 3^7 \cdot \frac{12!}{2} \cdot 2^{11} = 43{,}252{,}003{,}274{,}489{,}856{,}000 . \]

In 2010, Tomas Rokicki, Herbert Kociemba, Morley Davidson and John Dethridge used a large computer search to show that every one of these positions can be solved in 20 moves or fewer, counting a half turn as one move (cube20.org). The move list at the end of the clip above is a bit over 200 moves long.

The scanner

The Scan button in the solver window isn’t connected to anything. The scanning code is in two separate scripts. The first, from November 2021, reads webcam frames, converts them to HSV and picks out each of the six colours with hand-tuned HSV ranges. It runs Canny edge detection on each colour’s mask, with two sliders for the thresholds, and draws a box and a label on every contour bigger than 6000 pixels.

The second script, from August 2022, asks for the cube size and draws a grid of that size over the camera image. For each cell it runs k-means with a single cluster, which gives the average colour, and prints it. The function meant to turn that colour into a sticker name is still empty, and the script only ever asks for the green face.
